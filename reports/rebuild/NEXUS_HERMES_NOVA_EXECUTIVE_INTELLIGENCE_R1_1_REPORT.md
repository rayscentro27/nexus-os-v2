## Nova Tool Progress Model

`scripts/nova/tool_loop_recovery.py` fingerprints tool results and classifies
each call as `PROGRESS`, `TRANSIENT_FAILURE`, `STRUCTURALLY_BLOCKED`,
`SAME_FAILURE`, or `NO_NEW_INFORMATION`. It records tool, result fingerprint,
status, and whether new information appeared. HTTP/model success alone is not
treated as executive progress.

## Recovery Controller

The controller is a small turn-local wrapper around the existing Hermes loop.
On a guardrail halt it preserves the parent question and returned evidence,
records the failed method, and requests one tool-disabled synthesis continuation.
It cannot mutate Nexus, repeat a payment/write/publication, or recursively
retry forever.

## Temporary Tool Suppression

Suppression is scoped to the current recovery continuation. Only the repeated
failed tool/signature is marked unavailable there; the tool remains configured
for future turns. The Oracle adapter switches from `nexus_mcp_remote` to the
existing `skills` surface for the single synthesis pass, so the failed Nexus
tool is not re-invoked.

## Bounded Recovery

Recovery is capped at one automatic continuation. If recovery is unusable, the
original halt is retained as an honest result. This preserves Hermes'
anti-loop protection while preventing a method failure from being mistaken for
goal failure.
