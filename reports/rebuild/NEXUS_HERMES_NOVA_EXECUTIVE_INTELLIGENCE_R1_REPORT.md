# Nexus Hermes Nova Executive Intelligence R1

## Executive Result

`PARTIAL`. The existing Nova/Hermes architecture was reused and strengthened
with a bounded executive planning contract, parent-question decomposition,
dynamic specialist hints, durable process indexing, updated executive identity,
compact company context, and focused tests. The infrastructure remained
healthy. Live Oracle canaries showed one clear improvement—an explicit parent
decision and bounded test—but two strategic canaries still hit Hermes'
same-tool-failure guardrail. Full executive reasoning improvement is therefore
not certified.

No Compliance Department, pre-creative compliance gate, public publication,
payment, live trade, or new external authority was added.

## Nexus ↔ Hermes Capability Mapping

Nexus remains the durable company control plane. Hermes contributes native
conversation, session/tool execution, skills, and optional delegation. The new
planning module emits metadata only: complexity, parent question, likely
specialists, research need, recommendation need, and the parent-goal completion
rule. It does not execute tools or mutate objectives.

in `scripts/nova/test_executive_intelligence.py`. It covers review priority,

## Model Benchmark

The current route remains OpenRouter `openai/gpt-4o-mini`. Hermes 0.20.6
supports model/MoA surfaces, but no stronger approved route was selected or
paid for during this bounded campaign. Five live Oracle canaries were run
through `nova_nexus`; all returned process-level success, but two returned the
same-tool-failure guardrail instead of an executive answer. The post-change
free-vs-$97 canary returned a parent decision, competing assumptions,
recommendation, uncertainty, and a bounded pilot test.

## Model Decision

`NATIVE_ONLY — openai/gpt-4o-mini, with deterministic executive planning hints
and existing Nexus specialist/MCP tools.` A stronger model or MoA path should
be benchmarked only after tool-loop guardrail behavior is fixed and with the
same 20-case rubric. No arbitrary provider or paid usage was introduced.

## Query Complexity

`scripts/nova/executive_intelligence.py` classifies requests as
`SIMPLE_FACT`, `CURRENT_STATE_QUERY`, `SINGLE_SPECIALIST_QUERY`,
`MULTI_SPECIALIST_QUERY`, `MULTI_LEVEL_STRATEGIC_QUERY`,
`DURABLE_PROCESS_REQUEST`, `BROWSER_REQUIRED`, or `EXECUTION_REQUEST`.
Simple/current questions remain shallow; strategic and durable questions receive
decomposition and recommendation guidance.

## Multi-Level Question Reasoning

The plan preserves the parent question, identifies assumptions/unknowns,
selects only relevant specialists, and asks Hermes to compare contradictions,
separate evidence from judgment, recommend one reversible next action, and keep
the parent goal open until its success criterion is satisfied.

## Nova Identity

Updated both the profile identity and the runtime Nova identity to be curious,
recommendation-oriented, uncertainty-aware, contradiction-aware, and willing
to reroute a failed method while preserving the objective. Existing safety and
authority boundaries remain unchanged.

## Company Context

Added compact profile `AGENTS.md` context covering department roles,
goal/research/Alpha relationships, economic model, Mac/Oracle/Modal placement,
evidence distinctions, and approval boundaries. Full reports remain retrieved
through canonical state/resources rather than embedded in the prompt.

## Memory Architecture

The working architecture remains native Hermes session context plus the
canonical atomic Nova sidecar and Nexus objective/work-order persistence.
Conversational memory remains isolated; volatile company truth is still queried
on demand. The new process index records only durable-request metadata and the
latest bounded result, not a second evidence store.

## Memory Candidate Research

Decision: `KEEP_NATIVE`, with a later isolated pilot only if retrieval quality
falls short. Hindsight is MIT-licensed and offers temporal/entity/experience
memory, but adds a service and storage/LLM integration surface. OpenViking
unifies resources, memory, and skills and has persistent task tracking, but is a
larger context-database adoption. Mem0 is Apache-2.0 and multi-store oriented;
Graphiti is a temporal provenance-aware graph framework; Honcho is capable but
AGPL-3.0 and can be self-hosted. None was installed or allowed to replace the
proven sidecar/Nexus model.

Sources: [Hindsight repository](https://github.com/vectorize-io/hindsight),
[OpenViking context/session documentation](https://github.com/volcengine/OpenViking/blob/main/docs/en/concepts/08-session.md),
[Mem0 repository](https://github.com/mem0ai/mem0),
[Graphiti repository](https://github.com/getzep/graphiti), and
[Honcho repository](https://github.com/plastic-labs/honcho).

## Reasoning Extension Research

The official Sequential Thinking MCP provides dynamic step/branch/revision
semantics and is MIT-licensed, but it adds another tool-loop surface and
latency. Because current Nova already has a planning contract and the live
limitation is tool-loop repetition rather than absence of a thought schema,
the decision is `DEFER`, not install. Hermes native delegation/MoA remains the
first candidate for a controlled future A/B test.

Source: [official Sequential Thinking MCP documentation](https://github.com/modelcontextprotocol/servers/blob/main/src/sequentialthinking/README.md).

## Specialist Orchestration

Existing real Finance/Alpha multi-specialist receipts and Nexus MCP delegation
were reused. The new planner selects combinations based on question content
and avoids calling five departments for every request. Parallel candidates are
indicated for independent specialists; dependent work remains after its
prerequisite evidence.

## Contradiction Handling

The identity and skill contracts now require explicit disagreement attribution,
assumption comparison, targeted Research, and conditional recommendations.
Historical WP9S proves a real Alpha/Finance disagreement path, but this campaign
did not produce a new completed contradiction canary. Full new contradiction
certification remains open.

## Recommendation Quality

The post-change GoClear pricing canary opened with the parent decision, stated
free and paid assumptions, recommended a bounded pilot rather than claiming a
universal answer, and named uncertainty. This is a qualitative improvement in
one observed case. The opportunity canary still hit the repeated-tool guardrail,
so general recommendation quality is not certified.

## Decision Framework

`decision_framework()` provides a non-fabricating decision shape with question,
evidence, specialist positions, contradictions, unknowns, recommendation,
confidence, next test, and review trigger. It defaults confidence to `UNKNOWN`
and does not invent positions or evidence.

## Durable Process Management

Durable requests are recorded in the bounded Nova process index under
`data/runtime/nova_executive_processes/` and linked to the existing session and
parent question. Nexus remains the durable objective owner. The record keeps
the process `ACTIVE`/`ADVANCING`, preserves the latest result, and supplies a
next action; a completed turn cannot close the parent goal by itself.

## Goal Completion

The runtime guidance explicitly preserves `TASK_COMPLETE != GOAL_COMPLETE`,
`REPORT_COMPLETE != PROCESS_COMPLETE`, `FAILED_PATH != FAILED_OBJECTIVE`, and
`UNKNOWN != BAD`.

## Blocker Recovery

The existing Nexus ladder remains authoritative. The live canary exposed a
method/runtime guardrail issue, not a true external blocker. No new refusal or
Compliance gate was added. The next repair is to stop repeated same-tool loops
earlier and switch to synthesis/alternate evidence when the tool result is
non-progressing.

## Tool Discovery

Hermes native tools, MCP, skills, and tool-search surfaces remain available.
The planner provides semantic intent hints; it does not permanently inject all
schemas or replace Hermes discovery.

## Browser Reasoning

Oracle browser execution remains certified. The planning classifier recognizes
browser-required requests, but no unnecessary browser task was run in this
campaign because current-state MCP was sufficient for the canaries.

## Remote Compute Reasoning

Modal CPU remains certified and the company context tells Nova to place bursty
CPU work remotely while retaining the Mac as control plane. No additional
remote mutation was needed here.

## Failure Recovery

The durable process contract preserves the parent when a specialist, model, or
tool method fails. The live opportunity canary demonstrated the remaining gap:
Hermes stopped with `same_tool_failure_halt` after repeated non-progressing
calls. It did not falsely claim an opportunity result. A bounded alternate-path
repair is the next implementation item.

## Executive Prioritization

the recommended decision, and the exact approval boundary. It should not sort
by task creation time or report volume.

idempotency, retries, chunking, and schema-leak guards. The new format contract
puts the recommendation first, followed by compact rationale and a Ray decision
only when needed. No live Telegram publication was performed in this campaign.
