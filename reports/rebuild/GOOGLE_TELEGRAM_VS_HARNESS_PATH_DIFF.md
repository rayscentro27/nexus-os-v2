# Google Telegram vs harness path diff

The current Hermes runner is shared, but the real Telegram worker invokes it in
a fresh child process for each update with a stable chat session ID. The
canonical harness commonly reused one in-process session. The live sidecar
proved that the persisted rolling resource index contained Gmail, Calendar, and
Nexus rows together; referent selection used the last row globally. Thus a
later Calendar row could become the subject of a Gmail “which one?” turn.

The repair keeps process-per-turn behavior and changes only the persisted
referent selection contract: explicit active referent state is ordered ahead of
unrelated resource history and is cleared by a new unrelated conversational
turn.
