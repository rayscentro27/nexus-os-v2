# GoClear Future Page Blueprint Matrix

This matrix is a future implementation handoff. Territory B owns structure; A and C are selective influences.

| Page | Purpose / user goal | Primary CTA | Core modules | Empty behavior | B / A / C contributions | Icon / media / trust notes |
|---|---|---|---|---|---|---|
| Public landing/home | Explain GoClear and invite a safe first step. | Start your review | Hero, service promise, process, reassurance, FAQ | No client data. | B: clear path; A: premium polish; C: educational promise. | Hero image is purposeful, non-guaranteeing, alt-texted. Shield/check icons support trust copy. |
| Signup / login | Create or access a protected account. | Create account / Sign in | Branded form, support, privacy cue, reset help | No portal data before auth. | B: simple sequence; A: private visual shell; C: concise reassurance. | Lock/help icons; no Supabase terminology. |
| Email confirmation | Confirm identity and explain the next step. | Confirm my account | Branded subject/body, CTA, what happens next, support. | If link expired, explain recovery without losing context. | B: direct CTA; A: premium invitation; C: clear explanation. | GoClear branding; mobile email layout; no secrets or technical copy. |
| First-login onboarding | Collect only the facts needed to begin. | Continue setup | Welcome, goal, profile, situation, documents, review. | Never bypass to populated dashboard. | B: step sequence; A: calm form styling; C: why-this-matters copy. | Progress/arrow icons; no score or recommendation. |
| Client dashboard home | Orient the client at the current stage. | Complete current next step | Welcome, stage, next action, journey rail, upload/help. | Clean account shows not started/no records. | B: current-stage structure; A: hierarchy; C: current state/next. | Stage icons; optional quiet hero image only if it helps. |
| Credit review / profile | Prepare and explain the first review. | Complete profile / upload report | Profile facts, document readiness, review status, guidance. | No score until verified analysis exists. | B: gated sequence; A: private dossier; C: evidence explanation. | Document/clock icons; explain source and status. |
| Business foundation | Build relevant business context. | Complete the next requirement | Business profile, entity facts, requirements, help. | Show missing requirements, not readiness claims. | B: staged requirements; A: premium cards; C: rationale. | Building/file icons; no funding promise. |
| Funding readiness | Explain readiness after prerequisites. | Review readiness requirements | Verified readiness, missing evidence, next action, education. | Not available until prerequisites are met. | B: progressive reveal; A: high-value presentation; C: advisory evidence. | Target/check icons; state freshness and source. |
| Documents | Upload and track required documents. | Upload document | Requirements, upload, processing, reviewed, exceptions. | “No documents yet” plus why upload matters. | B: clear task order; A: secure vault feel; C: document explanation. | Upload/file/status icons; encryption language only when true. |
| Recommendations / action plan | Turn verified review into prioritized actions. | Review first action | Recommendation summary, evidence, priority, owner/status. | No recommendations before analysis. | B: next action; A: high-value card treatment; C: explain evidence. | Check/arrow icons; label estimated vs verified. |
| Resources / education | Answer questions without crowding action surfaces. | Read relevant guide | Stage-filtered guides, glossary, help. | Show relevant starter resources only. | B: stage relevance; A: curated feel; C: editorial education. | Book/help icons; no content dump. |
| Billing / payments | Show authorized payment state safely. | Review payment details | Offer, status, receipts, test/live boundary where appropriate. | No payment record becomes “No payment recorded,” not fake success. | B: clear state; A: restrained premium billing; C: explain what happens. | Receipt/lock icons; never expose keys or imply live charge. |
| Messaging / support | Let the client ask for help in context. | Ask Hermes / contact support | Hermes context, support route, conversation history. | Explain response availability; no fake messages. | B: contextual entry; A: discreet concierge; C: concise advice. | Message/help icons; filter operator data. |
| Future CRJ handoff / transition | Explain an approved external transition and return path. | Review and authorize handoff | Consent, data scope, compliance state, vendor status, expected return stage. | No case until authorized real handoff. | B: guided transition; A: trust/privacy; C: explicit evidence and rationale. | Handoff/lock/return icons; no vendor claim before receipt. |
