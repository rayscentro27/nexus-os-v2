# Nova Memory / Truth Boundary

Nova memory preserves conversation meaning and durable context. It is not an authority for volatile operational capability state.

## Conversational memory may preserve

- topics and referents under discussion;
- Ray’s expressed choices and decisions;
- business context and stable preferences;
- delegated-request context;
- useful historical conversation.

## Memory must not establish current facts

The following are volatile and must be queried from live capability truth when needed:

- web/provider availability;
- Gmail or Calendar authentication and callable status;
- Nexus runtime or worker health;
- current approvals, receipts, and work-order state;
- current reports, process counts, and service failures.

## Quarantine rule

Assistant messages containing stale capability assertions are archived as historical and excluded from the active prompt context. Historical records are retained and are not operational truth. The active session records `capability_state=QUERY_ON_DEMAND`.

This boundary does not restrict Nova’s reasoning or conversation. It prevents old model statements from masquerading as current capability evidence.

## Authority boundary

Nova may reason, read authorized information, research, and submit bounded requests. Nexus/TruthKernel remains responsible for authority, approval, execution, verification, and receipts. Memory cannot grant capability or authority.
